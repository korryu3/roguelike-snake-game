# ログスネ（RoguelikeSnakeGame） コンセプト

チームで決めた[検討事項](./roguelike-snake-検討事項.md)と、[コンセプトの抜けの議論](./discussions/2026-11-05-コンセプトの抜けの議論.md)の結論をまとめたもの。決めた理由は、議論の記録を参照する。

数値はすべて例で、遊んで調整する前提。

## コンセプト

**集めたPPでモジュールを買い、スネークを改造しながら、どこまでステージを進めるかを競う。**

## 前提

- 授業課題のデモ用。遊ぶのは先生
- 対応端末はPCのみ
- 日本語と英語を切り替えられる

## 呼び名

| 日本語 | 英語 | 意味 |
|---|---|---|
| ログスネ | RoguelikeSnakeGame | ゲームのタイトル |
| スネーク | Snake | プレイヤーが操作する機体 |
| バッテリー | Energy Cell | 盤面に出る、食べると長くなるもの |
| PP（Powerup Point） | PP（Powerup Point） | モジュールを買う通貨 |
| モジュール | Module | ステージの合間に買う強化。機体に取り付ける |
| ハート | Heart | HP。盤面に出る回復アイテムもハートと呼ぶ |
| スコア | Score | 成績 |

## 基本のルール

- 世界観はロボット・SF
- リアルタイム制（一定間隔で自動で進む）
- ステージがエンドレスに続く。死んだら最初からやり直し（メタ進行なし）
- 敵は出さない。長くなった自分の体が障害になる
- 盤面は15×15マス

## ステージ

- 壁の配置は、事前に作ったパターンの中からランダムに選ぶ。どのパターンも、盤面の中央とそのまわりを空けておく
- バッテリーは常に盤面に1個。食べると、次の1個が完全にランダムな位置に出る
- バッテリーをn個食べると、ランダムな位置にゴールが現れる。ゴールに入るとクリアになる
  - ゴールに入るまでは、バッテリーを追加で食べ続けられる。食べるほどPPは増えるが、体が長くなり、時間ボーナスも減る
- nは、ふつうに遊んで30〜60秒ほどでゴールが出る量にする
- 制限時間は、最大で2分ほど。ゴールが出たあとも減り続け、時間切れになったらゲームオーバー
- 進行バーは、食べたバッテリーの数（n個中いくつか）を表す。ゴールが出たら、満タンのまま光るなどして知らせる

## 長さ

- バッテリーを食べると長くなる
- 長さはステージをまたいで持ち越す
- ステージ開始時は、盤面の中央のマスに頭だけが現れる。進むにつれて、中央のマスから体が1マスずつ出てきて、元の長さまで伸びる
  - 盤面の中央は、周りより暗くする（穴は開けない）
- 難易度を上げる仕組みは、長さの持ち越しだけにする。nや制限時間をステージごとに変えるかは、遊んでから決める

## HPとダメージ

- HPの初期値は3。ハートで表す
- 壁や自分の体にぶつかると、HPが1減る。体は長くも短くもならない
- ぶつかったあとの動き
  - ぶつかった演出を少し入れて止まる（例: 1秒）。止まるかどうかと止まる長さは、遊んで調整する
  - 止まっているあいだに方向キーが入力されていればその方向に、入力されていなければランダムな方向に動き出す。何度か押されたら、最後に押された方向を使う
  - ランダムに選ぶのは、すぐ先が壁でも体でもない方向だけ。そういう方向が1つもないときは、4方向から完全にランダムに選ぶ（体で盤面が埋まって詰むのは許容する）
  - 動き出した瞬間から、短い無敵時間が付く

### ハート（回復アイテム）

- 取るとHPが1回復する。取っても体は伸びない
- 累計獲得PPが一定量を超えるたびに1個出る。加えて、バッテリーと一緒に超低確率で出る
- 取られるまで盤面に残る。同時に複数個あってもよい
- HPが満タンのときも出す。満タンのときに取ったら、何も起きない
- ステージが終わったら、残っていたハートは消える

### HPが0になったとき

- モーダルを出し、持っている「1回生き返る」系のモジュールと、「諦める」ボタンを並べる
- プレイヤーは、どのモジュールを使って生き返るかを選ぶ。「諦める」を選んだら、ゲームオーバー
- モーダルを出しているあいだは、制限時間を止める
- 生き返ったら、その場から無敵時間付きで再開する

## PPとスコア

- PP
  - モジュールを買う通貨
  - バッテリーを食べたときだけ、その場で増える
  - 使わなかったPPは、次のステージに持ち越す
- スコア
  - 成績。バッテリーの数×係数 ＋ 時間ボーナスで計算する
  - 時間ボーナスは、ゴールに入った時点の残り時間が多いほど多い。制限時間を延ばすモジュールは、時間ボーナスも増やす
- 到達ステージ数とスコアは、別々に扱う

## モジュール

- 買えるのは、ステージをクリアしたときだけ。ステージ中のレベルアップはない
- 10種類ほどの中から、ランダムに3つの候補を出す
- 3つのうち、PPが足りる限りいくつでも買える。何も買わずに「次のステージへ」を押してもよい
- PPを払うと、3つすべてを引き直せる（リロール）。買ったあとでも、3つすべてが新しくなる
- 3つすべてを買い切ったら、無料で自動リロールする。回数の制限はなし
- 同じモジュールを重ねて買え、効果も重なる。強くなりすぎるものには上限を設ける
- 良いモジュールほど高い。メリットとデメリットの両方があるモジュールも入れる

### 必ず作るモジュール

| モジュール | 効果 |
|---|---|
| PP・伸び2倍 | バッテリー1個で得るPPが2個分になり、体の伸びも2マスになる。スコアのバッテリーの分は2倍にしない |
| 1回生き返る | HPが0になったとき、HPが満タンの状態で生き返る。高額 |
| 1回生き返る（デメリット付き） | HPが0になったとき生き返るが、HPは1で復活する。少し安い |
| 制限時間＋5秒 | 制限時間を5秒延ばす。恒久的 |
| 制限時間の一時延長 | 次のステージだけ、制限時間を延ばす |
| 壁ダメージ無効 | 壁にぶつかってもダメージを受けない（1回だけ、開始数秒だけ、など）。ぶつかったときの動きは、ダメージを受けたときと同じ。自分の体にぶつかったら、ダメージを受ける |
| HPの上限＋1 | HPの上限が1増え、現在のHPも1増える。上がり幅に上限を設ける |
| PP2倍のバッテリー | n%の確率で、PPが2倍のバッテリーが出る |

### できたら作るモジュール

- ステージクリアに必要なバッテリーの数が増える。PPは増えるが、クリアが難しくなる
- 体の一部を切り落とす（例: 次のステージで、自分の体にぶつかった位置から先を切断する。使い切り）
- n%の確率で、モジュールの候補が4つに増える
- 移動速度1.5倍
- 移動速度が落ちるが、PPの倍率が少し上がる

## 画面

### 画面遷移

タイトル → ステージ → クリアのモーダル → モジュールのモーダル → 「次のステージへ」 → 次のステージ → …（エンドレス）

HPが0になったら、生き返るモーダルを出す。ゲームオーバーになったら、ゲームオーバー画面に移る。

### タイトル

- 「ゲーム開始」ボタン
- 日本語と英語を切り替えるボタン

### ステージ中

- 進行バー
- スネークを操作する盤面
- これまでに買ったモジュール
- HP（ハート）
- ステージ番号
- 所持PP
- タイマー
- 操作方法（右下などに、WASDで操作することをUIとして書く）

### クリアのモーダル

- クリアしたステージの番号
- 獲得したPP
- 獲得したスコア（バッテリーの分、時間ボーナスの分）
- クリアにかかった時間

### ゲームオーバー画面

- 到達ステージ
- スコア
- 死因（HPが0になった / 時間切れ）
- 累計獲得PP
- 残っていたPP
- 最終的な長さ
- 買ったモジュールの一覧
- 「もう一度」と「タイトルへ」のボタン

## 最初の完成ライン

これができたら、「できたら作る」モジュールを足していく。

- 画面遷移の一式（タイトル → ステージ → クリア → モジュール → ゲームオーバー）
- 必ず作るモジュール8種
- 壁のパターン3種類
- ハート
- 日本語と英語の切り替え

## 作るときの方針

- 説明なしで遊べるようにする。最初の画面で操作方法が分かること
- 見た目のインパクトより、ルール同士がかみ合っていることを優先する
- コンセプトの説明は発表スライドに任せる。ゲームは説明に頼らず、作品として完成させる

## 実装しながら決めること

- 移動速度や曲がるときの反応などの数値
- エフェクトや画面の揺れの強さ
- 難易度曲線とバランスの数値（モジュールとリロールの値段、ハートが出る基準など）
- 死んでから再挑戦するまでの手間
- 死因の分かりやすさ
- チュートリアル
- 一時停止、別タブに移ったときの自動停止、中断したプレイの再開
- モジュールの説明の見せ方
- アクセシビリティ（色だけに頼らない、矢印キーとWASD、速度を遅くするオプション）
