# Vite+への切り替え（2026-11-07）

**状態: 決定**

[開発の仕組みと各層の見直し](./2026-11-07-開発の仕組みと各層の見直し.md)で、vite・vitest・oxlint・oxfmt・pnpm・miseを個別に入れた。その後、これらを1つにまとめたVite+（`vp`コマンド、MITライセンス、2026年9月に1.0）に切り替えることにした記録。中で使う道具は同じなので、lintや整形の結果は変わらない。変わるのは、呼び出し方と設定の置き場所。

## 決めたこと

### Q1. 進め方

- **結論**: マージ待ちのPR（#22〜#25）の上に積む
- **理由**: 基盤は#22から変えていないので、下のPRに修正が入っても衝突しにくい

### Q2. nodeとpnpmの版

- **結論**: miseをやめる。nodeの版は`package.json`の`devEngines.runtime`、pnpmの版は`packageManager`に書き、`vp env`が読む。CIは`voidzero-dev/setup-vp`で、`package.json`から読んだ版のnodeを入れる
- 各自、`vp`をグローバルに入れる
- **理由**: 道具を1つにまとめるのが乗り換えの目的。`mise exec -- pnpm`の回り道もなくなる。版を`package.json`の1か所にそろえる
- 最初はリポジトリ直下の`.node-version`に書いたが、`mise.toml`の場所を引き継いだだけで理由がなかったので、`package.json`に移した
- `devEngines.runtime`の`onFail`は既定のまま。手元のnodeの版が違っても（例: voltaの24.15.0）、`vp install`は止まらないことを確かめた

### Q3. 型検査

- **結論**: `vp check`（整形の検査、lint、型検査）にまとめる。CIは`vp check`、`vp test`、`vp build`の3つ。`build`の中の`tsc --noEmit`と、`typecheck`のスクリプトはなくす
- `vp check`の型検査が、入れてあるTypeScriptの版で正しく検査できなければ、`tsc`を残す

### Q4. lintと整形の設定

- **結論**: `.oxlintrc.json`と`.oxfmtrc.json`を、`vite.config.ts`の`lint`と`fmt`にまとめる。層の依存の向きの検査も、`lint.overrides`で書く
- 書けなければ、`vp lint -c`で今のJSONを読む

### Q5. Gitのフック

- **結論**: 入れない。前に決めたとおり、検査はPRのCIで回す

### Q6. 版の固定

- **結論**: `vite-plus`は正確な版で固定する。CIの`setup-vp`も正確な版で指定する。pnpmの`minimumReleaseAge`は緩めない

### Q8. 型を使うlintルール

- **結論**: `vp check`で型検査を有効にすると（`lint.options`の`typeAware`と`typeCheck`）、型を使うlintルールも有効になり、今のコードで18件のエラーが出た（`no-unsafe-type-assertion` 14件、`consistent-return` 2件、`no-misused-spread` 2件）。この3つは切っておき、型の整理（zod）でコードを直すときに戻す
- **理由**: 道具の乗り換えとコードの書き換えを1本に混ぜない
- ※ 当初は「`no-unsafe-type-assertion`の多くは、外から読む値をzodで検査すれば消える」と書いたが、実際にzodで消えるのは14件中4件ほどだった。戻し方は[外から読む値の検査と型の整理](./2026-11-07-外から読む値の検査と型の整理.md)のQ4を参照する

## 切り替えてみて分かったこと

- `vp migrate`は、`.oxlintrc.json`と`.oxfmtrc.json`を`vite.config.ts`にまとめなかった。さらに、既定の行の幅（80）で整形し直した。設定は手で移し、整形は元の幅（120）でやり直した
- `vp check`は、`lint.options`で`typeCheck`を有効にしないと、型検査をしない
- グローバルの`vp`（Homebrewで入れたもの）は、プロジェクトに固定した`vite-plus`の版を使う
- `vp env`は、既定ではほかの道具（miseなど）が入れたnodeを先に使う。`vp`のnodeに切り替えるには、各自`vp env setup`と`vp env on`を実行する
