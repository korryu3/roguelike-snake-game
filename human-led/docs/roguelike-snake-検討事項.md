# ローグライク風スネークゲーム 検討事項

## 前提

- 期間: 1週間
- 実装はAIを積極的に使う
- コンセプトとコア部分は人間が決める

## 人間が決めること（着手前）

| # | 決めること | 選択肢の例 | これで決まるもの | 状態 |
|---|---|---|---|---|
| 1 | 目的と遊ぶ人 | 自分用 / 友人 / ポートフォリオ / 投稿サイト | 作り込みの深さ、ほかの全項目の優先度 | 未定 |
| 2 | 完成の定義（最初の公開範囲） | 例:「ステージ3つと強化5種で公開」 | 作業量、終わりどころ | 未定 |
| 3 | 時間の進み方 | リアルタイム（一定間隔で自動移動） / ターン制（入力したときだけ進む） | ゲームループ、入力処理、難易度の考え方 | 未定 |
| 4 | 1回のプレイの構造 | エンドレス / ステージ制（クリア条件あり） | マップ生成、進行管理 | 未定 |
| 5 | 長さの意味 | 不利なだけ / HP / 攻撃力 / スコア倍率 | 戦闘や強化の設計の土台 | 未定 |
| 6 | プレイ中の成長の形 | ステージの合間に3択の強化 / 拾うアイテム / なし | 状態のデータ構造 | 未定 |
| 7 | 世界観とテーマ | ダンジョン / 宇宙 / 体内 / 抽象 | 敵、アイテム、強化の名前と見た目 | 未定 |
| 8 | 見た目の方向性 | ドット絵 / 図形だけのミニマル / 手描き風 / ネオン | 素材の作り方、描画方式 | 未定 |
| 9 | マス目と画面構成 | 下記参照 | 難しさ、見やすさ、UIの配置 | 未定 |

3〜6がゲームの骨格。ここが変わると、状態の持ち方とロジックを作り直すことになる。

### マス目と画面構成でざっと決めること

- 盤面のマス数（例: 20×20）。狭いと序盤から窮屈になり、広いと間延びする。最初は仮の数字でよい
- 盤面の周りに置くもの（スコア、長さ、HP、所持している強化、ステージ番号）
- 強化を選ぶ画面の出し方（盤面の上に重ねるか、画面を切り替えるか）

手描きの落書きでも、AIに渡せば画面にできる。

## AIの提案を採用してよいこと

- 技術の構成（素のTypeScript + Canvas 2Dで十分。演出を凝るならPixiJSやPhaser）
- 対応端末（1週間ならPCのみがおすすめ。スマホ対応ならスワイプ操作が要る）
- 素材の用意（図形のみ / AI生成 / フリー素材。見た目の方向性から決まる）
- 音（効果音のみで十分）

## 作りながら決めてよいこと

- 敵や戦闘の有無と攻撃方法
- メタ進行（死んだ後に残る強化）
- ランダム生成の対象と強さ
- 手触りの調整（移動速度、曲がるときの反応、エフェクト、画面の揺れ、効果音）
- 難易度曲線とバランスの数値、壊れビルドをどこまで許すか
- チュートリアル（最初のステージに組み込むのが軽い）
- 一時停止、別タブに移ったときの自動停止、中断したプレイの再開
- 強化や敵の説明の見せ方
- アクセシビリティ（色だけに頼らない、矢印キーとWASD、速度を遅くするオプション）
- 公開先（静的ホスティングならどこでも移せる）
- ランキング、アクセス解析

## 実装で押さえること

- **ロジックと描画の分離**: `step(state, input) => state` のような純関数にする。テストしやすく、AIが自分で検証しやすい
- **シード付き乱数**: `Math.random`を使わない。プレイの再現、テスト、デイリーチャレンジに使える
- **入力バッファ**: 1回の移動の間に「上→左」と素早く押すと逆方向に反転して自滅するバグが起きやすい。押されたキーを順に溜める
- **固定タイムステップ**: リアルタイムにするなら、画面の更新とは独立した一定間隔で状態を進める
- **バランスの数値は設定データにまとめる**: コードに直接書かない
- **自動プレイのシミュレーション**: ボットに大量に遊ばせて、平均到達ステージなどを測れる

## 遊び心地で押さえること

- 死んだら1キーですぐ再挑戦できる
- なぜ死んだかが分かる（理不尽ではなく「もう1回」になる）
- 長くなるほど危険だが見返りもある、という釣り合い

## 公開

- サーバーなしの静的サイトで足りる（GitHub Pages、Cloudflare Pages、Netlify）
- ハイスコアは`localStorage`に保存する
- オンラインのランキングはサーバーかBaaSが要るので、最初は外す
- 画像、音、フォントのライセンスとクレジット表記の条件を確認する

## AIで作る前提で必要なこと

- 決めたことを1つのコンセプト文書にまとめ、AIへの指示の前提にする（セッションをまたいでもぶれない）
- 面白いかどうかは人間が遊んで判断する。毎日遊ぶ時間を取る
- 2日目には最低限遊べる形にして、コアの仕組みが面白いかを確かめる

## 1週間の目安

| 日 | やること |
|---|---|
| 1日目 | コンセプトを決めて文書化。素のスネークを動かす |
| 2〜3日目 | コアの仕組み（長さの意味、成長、プレイ構造）を作る。遊んで調整する |
| 4〜5日目 | 内容を増やす（強化の種類、ステージ、敵） |
| 6日目 | 見た目、音、手触りを仕上げる |
| 7日目 | 公開と予備日 |
